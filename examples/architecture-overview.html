一、系统架构

教练（Trae）→ 编码 agent（Claude Code）→ 文档 agent（Hermes），人做中继；一切判断以左栏账本为唯一事实，右道检测器只做账本重放。

二、一条证据的落账（触发 → 预检 → 加工 → 校验 → 写账 → 推锚 → 扇出/对账）

三、防伪与重复处理（判定链 + 重复执行时各存储的动作）

存储/组件主键与守卫重复执行同一条时
events.jsonlseq + prev + self 三重拒绝：重放=断链；事后改=重算不一致
checkpoint.json单调门（seq 只进不退，同 seq 不许换 hash）锚不动；幻影锚（写了个不存在的 seq）由 append 真实成功后用尾部覆盖
sweep 巡逻already-observed guard + settle 双读同一磁盘事实只记一次（O5-02 修复：落账前逐文件对尾部做新鲜复读）
trigger 队列无状态重放重复显示是设计（永久长鸣）；去重只发生在人/教练的阅读端
record-edit 补账no-op 守卫（盘==已记即拒）拒绝：不许造无新信息的记录
sign-gate 签字控制字符拒收 + 拒完全重复的旧理由拒绝：同文案≠新决定

五、自洽审计 · 矛盾清单

【冲突 1】逻辑冲突 / 高
冲突点：同一不变量两个出口打架——audit C1 已改为「幻影锚禁止盲目 restore bak」，但 trigger 的 T1 队列文案仍写着「restore from events.jsonl.bak-*」。
为什么会被问：教练/人按 T1 文案执行 = 把 1058 条账截回昨天；两个官方口径不一致本身就是审计事故（今天真实发生过同型：教练交接词推荐了已被证实毁损的交互通道）。
建议处置：改设计——trigger T1 复用 C1 的 history 诊断文案，单一出口（代价：一次部署+重封锚，10 分钟）。

【冲突 2】逻辑冲突 / 高 ——【已处置 11-09 下午】
冲突点：图上「PreToolUse 快照」声称覆盖写前图像，实际 matcher 仅 Edit/Write/MultiEdit；hermes 与 Bash 通道无图像——52 条 tool_use 有 file 无 before，runtime.yaml 旧字节已永久丢失（O5-06）。
处置：pre-tool 接 Bash（matcher 已加）——每次 Bash 前全项目源文件 manifest + 边界间 diff 入 .harness/local/prebash-diff.jsonl（259 文件 170ms 实测）；verify 加 universe_changed（判决期间动过的 undeclared 文件入账，T15 点名）。仍盲：hermes 自有工具链（只有轮询）、内存 monkeypatch。历史损失（86440bac）不可逆，此句永久保留。

【冲突 3】数据冲突 / 中 ——【部分处置 11-09 下午】
冲突点：T14 防「考卷变动」，但若判卷器本身是产物，「写了判卷器」＝「产物动了」→ 该类步骤 T14 永久失效；真实账上它至今 0 投递。
处置：拆出 T14b_exam_only（FAIL→PASS 且判决窗口内唯一移动的产物是判卷器 = 点名，不再豁免）+ T15_universe_moved（世界移动最小盘模型）。仍豁免：products 字段上线前的历史翻转（append-only 构造限制）；内存 monkeypatch 不在盘像模型内——hermetic verify 条款仍待教练立项。

【冲突 1】逻辑冲突 / 高 ——【撤案：误报】
原指控：trigger T1 队列仍写「restore from bak」而 audit C1 已修。核实：trigger 只是忠实重放 seq 940 时代 deviate 记录的历史原文（alternatives 字段内容）——视图不该改写历史。真修复只有 C1 文案本身（已完成）。教训入 CASEBOOK：审计别人的文案前，先分清「生成的建议」和「重放的记录」。

【冲突 4】职责冲突 / 中 ——【已处置 v2.3.10】
处置：教练卡 v2.3.10 —— 复制纪律：转发给 agent 的一切（四层指令/交接提示词/命令）整块可粘贴；gate 理由不可粘贴，人写 UTF-8 文件走 -WhyFile（签字必须经过人的手和眼）。

【冲突 4】职责冲突 / 中
冲突点：教练卡、人、我三方都当过「签字通道的权威口径」，但通道事实只有一份——v2.3.8 的交接词仍教交互粘贴，与 harness 的实测结论（三次毁损）相反。
为什么会被问：流水线里「谁的说明书是最新的」没有机制保证——PROMPT 版本检查管住了 agent 侧，没管住「人转述的操作指引」。
建议处置：改设计——v2.3.9 交接词固定写 -WhyFile；并把「教练文案里的命令必须在 harness 里真实存在且走通」做成教练自检条目。

【冲突 5】悬空组件 / 低
冲突点：real_test 判定只对新证据生效，历史 18 条 trivial=true 无从改判——视图里「有证据的步骤」对它仍是一半信任。
为什么会被问：「1.1–1.4 的 done_without_evidence 警告是不是就是它？」——是，且账本原则（append-only）决定了不能修，只能带着警告收口。
建议处置：备话术——保留警告并说明「毁证不可追溯，前向从严」正是 append-only 的代价，属有意取舍非遗漏。
